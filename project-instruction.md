# CLAUDE.md — Horror Game Jam Project

## Project Context
- Game jam entry, **4-day deadline**. A complete, polished small game beats an unfinished big one.
- Theme: **anything Scary**
- Engine, language, and final concept are **not decided yet**. Do not assume any engine or write engine-specific code until they are set here.

## Jam Restrictions (ALL must be visibly present in the game)
1. **Misleading signs** — fake instructions, notes, signs, or UI that lie to the player
2. **One rule** — exactly one objective to finish the game
3. **Something is pretending** — doppelgangers / "I'm not human" style entities
4. **Haunting sounds** — sound is a core gameplay mechanic, not just ambience

When evaluating any idea or feature, check it against all 4 restrictions.
Prefer designs where restrictions reinforce each other
(e.g. misleading signs try to trick the player into breaking the one rule).

## Scope Rules
- Small scope: ideally one main scene/location.
- Core loop must be playable by end of Day 1 using placeholder art.
- Prefer data-driven content (entities, notes, dialogue) so content can be added without code changes.
- If a feature can't be finished in about half a day, flag it and propose a smaller version.
- No new features on Day 4 — polish, bug fixes, and build only.

## Daily Plan
- **Day 1:** decide concept + engine, build the core loop
- **Day 2:** content (fake signs, pretending entities, endings)
- **Day 3:** sound design + art pass
- **Day 4:** playtest, fix, build, submit

## How to Work With Me
- Reply to me in **Thai**; code, comments, and commit messages in **English**.
- Before writing code, briefly state the plan and any assumptions.
- Keep changes small and focused; don't refactor unrelated code.
- When something breaks, explain the debugging reasoning, not just the fix.
- Be direct about bugs and bad design choices.
- After each feature, tell me exactly how to test it.
